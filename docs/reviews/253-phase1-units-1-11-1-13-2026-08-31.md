## Unit 1.13 — `src/components/VenueCalendar.tsx` (713 → 705 lines)

Not a clone-stamp admin panel (no giant destructure; `useConfirm()` at line 91) — the calendar is original code that had simply never been type-checked. 9 tsc errors on de-blinding, triaged as:

**F-253-1 (P1 runtime bug — fixed): the add/edit event form crashed on open.** The `CalendarEventForm` sub-component (line 540) referenced `config` (branding) that exists only in the parent `VenueCalendar`'s scope (`const config = useBrandingConfig()` at line 78) — never passed as a prop, never called in the sub-component. The form's Save button evaluates `config.primaryColor` in its style **on every render**, so clicking "+ add event" or "Edit" on any calendar entry threw `ReferenceError: config is not defined` and crashed the component tree: event creation and editing have been broken since the form component was written. Fixed by giving `CalendarEventForm` its own `useBrandingConfig()` call (hook already imported at module level). Its staff-assignee toggle styles (the other out-of-scope `config` reads) are covered by the same fix.

**F-253-2 (P4 display bug — fixed): event end times never displayed.** `EventItem` (the local calendar-entry type) carried `startTime` but not `endTime`, and `venueItems` construction never copied it — so the detail panel's `"start – end"` branch rendered end time as empty for every event, even though `VenueCalendarEvent.endTime` exists and the form saves it. `endTime?: string` added to the interface and copied at construction.

Cosmetic alongside: 2 sites of `setEditEv(e.venue)` were truthy-ternary-guarded but TS couldn't narrow across the callback boundary — now `e.venue ?? null`. Dead code pruned: `monthEvents` useMemo (computed a month-filtered list nothing consumed — day cells use per-day lookups) and unused imports `CoupleEvent`, `getVenueCalendarEventsInRange`.
