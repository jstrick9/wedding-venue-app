## 3. Deferred (documented, per user direction)

- **Phase 3 venue-intelligence features** (booking/contract/deposit lifecycle, space×time double-booking, pull/return inventory ledger, rotation-aware collision, day-of decision support) — deferred.
- **P0-2 / N-4 / P1-9 — couple→org_data/relational projection.** Console `coupleEvents/coupleGuests/coupleSubmissions` metrics still read from local-only domains, so they read 0 until a server-side couple projection exists. This is the single largest remaining piece of "cloud honesty."
- **P1-7 RBAC unification** (two authorities + role short-circuits) — deferred; needs an authoritative-service refactor.
- **P1-11 invite acceptance AuthContext refresh** — deferred (needs AuthContext plumbing).
- **N-3 tokens in couple snapshot payload at rest.** Deliberately NOT changed to hash-only: the couple portal's guest-management UI (copy/email/remind guest links) requires the raw guest token after cloud hydration; stripping it would regress that feature. Mitigations are in place: guest-facing RPCs strip tokens from all responses (`guest - 'token'`, `rsvp - 'token'`), `tokenHash` is stored for verification, the snapshot is RLS-restricted to owner/admin/planner, and backup/export redacts all tokens (P1-8).
- **`@ts-nocheck` removal, re-enabling the 11 skipped tests, browser E2E/axe** — deferred to a dedicated quality pass.
