## 2. Cloud honesty after this change

When `VITE_BACKEND_PROVIDER=supabase` is configured and a venue member saves couple data:

1. Couple domains are upserted into `org_data` (already syncable; now explicitly flushed on couple writes).
2. `sync_couple_projection` writes relational `events` / `guests` / `rsvp_submissions` / `guest_portal_configs` keyed by source ids.
3. Guest portal tokens are hashed into `guests.portal_token_hash`, so `get_guest_by_portal_token` / `submit_guest_rsvp` can resolve couple-managed guests.
4. `get_platform_console_metrics` counts the projection (or a correctly-parsed org_data array), so `total_couples` / `total_guests` / `total_rsvps` stop reading 0 once a venue has projected data.

This path is **not live-certified**. Apply migration `0011` and run a device-A / console metrics smoke test before claiming production readiness.
